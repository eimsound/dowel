# 上手指南

本指南说明如何在本地启动 Dowel、初始化实例、创建项目并完成从模型编辑到目标库执行的最小闭环。完整运维参数、账户体系和各数据库方言细节见对应专题文档。

## 1. 启动服务 {#start-service}

使用 Docker Compose 启动单容器服务（默认使用卷 `dowel-data` 中的 SQLite 文件作为平台库）：

```sh
docker compose up -d
```

启动前建议修改根目录 `docker-compose.yml` 中的 `DOWEL_SECRET`，将其替换为至少 16 个字符的随机字符串。`DOWEL_SECRET` 用于加密保存在平台库中的数据库连接串、OIDC 客户端密钥和 Webhook 密钥，设置并保存环境后不要更改。

若需从源码运行、配置外部 PostgreSQL 平台库、设置多副本高可用或配置反向代理，见 [部署与配置](deployment.md)。

## 2. 初始化与建组 {#setup-and-group}

1. 首次启动且实例尚无用户时，服务端会自动创建初始实例管理员（用户名默认为 `admin`，可通过 `DOWEL_ADMIN_USERNAME` 修改）：
   - 未配置预设密码时，服务端会生成随机临时密码，并以 `0600` 权限写入数据目录的 `initial-admin-password` 文件（Docker Compose 下位于 `dowel-data` 卷的 `/data/initial-admin-password`，日志仅打印文件路径，不输出明文密码）；
   - 从该文件读取临时密码，打开 <http://localhost:4600> 登录 `admin`，系统会引导进入修改密码页面，设置新密码并自动清理 `initial-admin-password` 文件；
   - 如需在启动前直接指定正式密码，可通过 `DOWEL_ADMIN_PASSWORD_FILE` 或 `DOWEL_ADMIN_PASSWORD` 配置（二者互斥）。
2. 登录后前往“管理后台”或项目首页新建一个组。所有项目都归属于某个组，访问路径为 `/project/<组标识>/<项目标识>`。

用户邀请、OIDC 外部登录和权限模型见 [账户、OIDC 与权限](accounts-and-access.md)。

## 3. 新建项目（四步向导） {#create-project}

在“我的项目”页面点击“新建项目”（或按 `⌘K` 打开命令面板选择“新建项目”），进入 `/new` 向导：

1. **基本信息**：选择所属组、输入项目名称与标识，并选择目标库方言：
   - **PostgreSQL**（15–19）
   - **SQLite**（使用本地 SQLite 文件作目标库时，服务端需预先配置 `DOWEL_SQLITE_ROOTS`；只做建模与 SQL 导入时无需配置环境，内置 `:memory:` 影子库）
   - **MySQL**（8.4 / 9.7）
   - **SQL Server**（2019 / 2022 / 2025）
2. **关联数据库**：添加一个或多个环境（例如 `dev`、`staging`、`prod`）。点击“检查连接”可探测数据库版本、当前账号权限及已有表数量。
   - 对 SQLite 项目，这一步可跳过：SQL 导入与验证默认使用内置 `:memory:` 影子库。
   - 对 PostgreSQL、MySQL 与 SQL Server 项目，导入 SQL 和验证迁移需要至少一个可用的真实数据库影子库（默认在目标实例上自动创建 `{原库名}_dowel`，也可在环境配置中指定独立影子库；生产环境默认不在同一实例上建影子库）。
3. **初始内容**：可选择四类起点之一：
   - **空白模型**：从方言默认 schema 起步（如 `public`、`main`、`default`、`dbo`）；
   - **从数据库导入**：从已关联的环境中读取现有结构（只读，不修改目标库）；
   - **从 SQL 导入**：粘贴或上传 `.sql` 建表脚本，在影子库执行后读出结构；
   - **接手现有项目**：从存有 `dowel` 迁移历史的目标库恢复完整版本链与对象 ID（详情见 [接手现有项目与灾难恢复](takeover.md)）。
4. **确认创建**：核对项目与环境汇总信息。导入类项目会在创建后自动发布 `v0 · 基线` 版本。此步骤只写入 Dowel 平台库，不会向目标库写入数据或创建 `dowel` 历史表。

## 4. 编辑模型与发布版本 {#edit-and-publish}

1. 进入项目画布页，拖放表位置或打开右侧属性面板编辑表、列、主键、唯一约束、外键、CHECK 约束、索引及方言专属属性。
2. 调整表名或列名时，Dowel 按对象 ID 保留同一对象，自动更新推导名与表达式引用；修改过程可通过右上角入口浏览**画布修改历史**并在需要时一键恢复。
3. 编辑完成后点击**发布**，输入版本名称将工作副本冻结为新的不可变版本（同时生成对应的升级 `up` 与回滚 `down` 迁移脚本）。

详细建模规则、导入权限、影子库隔离边界与 PostgreSQL 分区表编辑见 [建模、版本与画布历史](modeling.md)；各数据库支持的语法与版本差异见 [多方言与版本支持](dialects.md)。

## 5. 在影子库验证迁移 {#verify-migration}

打开“版本”或“迁移”视图，选择任意两个版本生成升级与回滚脚本，点击**在影子库验证**：

- Dowel 会在对应方言的影子库中执行升级脚本并核对结果结构等于目标版本，再执行回滚脚本核对回到源版本（闭环验证）；
- 同步生成逐步风险摘要（锁类型、整表重写、全表扫描或 `INSTANT` / `INPLACE` / `COPY` 算法分级）；
- 若目标数据库为 PostgreSQL 或 MySQL 且项目内存在多个大版本/主次版本环境，Dowel 会按版本组分别在对应影子库完成实测。

也可以直接下载带固定会话设置的 `.sql` 迁移脚本手动执行。

## 6. 预演并执行到目标库 {#apply-to-target}

在“环境”详情页点击目标版本的**执行**（或回滚到较早版本）：

1. 确认对话框打开时会自动触发一次**预演（dry run）**：只读检查项目锁、版本链完整性、实例认领归属、线上漂移状态、验证状态与历史表写权限，不修改目标库。
2. 预演通过后确认执行（生产环境需输入环境名称确认）。若环境配置了审批环节，按钮会显示为“提交执行申请”，经审批通过后再执行。
3. 首次向某目标库执行时，Dowel 会创建 `dowel` schema（SQLite / MySQL 为同库 `dowel_` 前缀表），写入执行历史，并在每一步迁移后读回目标库结构校验一致。
