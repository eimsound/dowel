# 术语表

本页定义 Dowel 中使用的核心概念与专有名词，帮助在团队协作和界面操作中统一理解。

## 账户与归属 {#accounts-and-ownership}

- **实例（Instance）**：一个独立的 Dowel 部署，只服务同一家公司或组织。
- **用户（User）**：在实例内拥有唯一用户名、通过用户名和密码（或外部 OIDC 身份）登录的操作者。邮箱仅作为可选个人资料字段，不用于登录或找回密码。
- **实例管理员（Instance admin）**：管理整个实例的用户，可查看实例中的全部组、项目与审计日志，并拥有所有权限。
- **组（Group）**：由若干用户组成的协作单元，可以拥有项目。组本身（名称、成员列表）对所有已登录用户可见，组内项目只对有权限的成员可见。
- **组管理员（Group admin）**：管理某个组的成员、组级执行策略、组级 Webhook 以及组内项目默认权限的成员。

## 权限与治理 {#permissions-and-governance}

- **项目角色（Project role）**：用户对项目模型的访问与编辑级别，分为**查看者（Viewer）**、**编辑者（Editor）**、**项目管理员（Admin）**三级。项目角色控制模型编辑与发布，不直接等同于生产目标库执行权。
- **默认权限（Default permission）**：组成员对本组项目自动拥有的项目角色。每个组设有一项默认值，组管理员可为单个项目覆盖设定。
- **授权（Grant）**：在“单个环境 / 单个项目 / 组的全部项目 / 整个实例”四个范围之一，将某个项目角色或执行者角色授予特定用户或组。
- **执行者（Executor）**：被单独授权可在指定范围内执行特权操作的用户或组（例如 DBA 组），在任何“谁能执行”档位下均保有执行资格。
- **特权操作（Privileged operation）**：直接作用于目标数据库或削弱环境防护的操作，包含执行、回滚、写入基线、标记为已执行、修改连接串或影子库配置、取消生产标记、删除环境以及为已有项目接入已有历史。模型编辑和发布不属于特权操作。
- **执行策略（Execution policy）**：按实例 → 组 → 项目 → 环境四层配置、逐层只收紧不放宽的规则集，用于控制谁能执行、锁与语句超时、是否允许 CI 令牌执行、申请有效期与审批流程。
- **执行申请（Execution request）**：请求将指定环境从当前版本升级或回滚到目标版本的申请，按环境的审批流程逐环节审批通过后方可触发执行。
- **紧急执行（Emergency execution）**：仅实例管理员可触发的应急动作，绕过审批流程直接执行（或回滚）到指定版本；必须填写原因，且不绕过漂移、完整性、认领和已验证检查，执行结果写入审计并通知该环境全部审批人。
- **审批流程（Approval flow）**：执行策略中规定的、按先后顺序排列的一串审批环节；最简单的默认流程只包含 1 个环节。
- **审批环节（Approval stage）**：审批流程中的一步，定义有资格审批的人员范围与所需确认人数。
- **CI 令牌（CI token）**：归属于单个项目的长期自动化凭据（必须配置过期时间，最长 365 天）。只能在开启了“允许 CI 令牌执行”的环境上免审批向前执行及查询状态，不能修改模型、发布版本或回滚。

## 项目与环境 {#projects-and-environments}

- **项目（Project）**：归属于某个组的建模单元，绑定单一数据库方言，包含一个实时协作的工作副本、一条版本链和若干环境。
- **环境（Environment）**：项目部署的目标实例映射，例如 `dev`、`staging`、`prod`。一个环境对应一个目标库，不同环境彼此独立运行。
- **目标库（Target database）**：环境所指向的真实数据库，迁移脚本最终在该库上执行，Dowel 在其中记录迁移历史。
- **影子库（Shadow database）**：专用于验证的独立数据库。SQL 导入、表达式规范化、闭环验证和锁/重写风险分析都在影子库上执行，绝不修改业务目标库数据。SQLite 使用内置 `:memory:` 影子库，PostgreSQL / MySQL / SQL Server 使用配置的独立影子库或同实例 `{原库名}_dowel`。
- **导入（Import）**：从目标库系统目录或一段 `.sql` 脚本中读取结构以生成或更新项目模型（只读取结构，不读取业务数据，也不恢复历史链）。
- **接手（Takeover）**：从目标库内 `dowel` schema（SQLite / MySQL 为同库 `dowel_` 前缀表）的历史记录恢复出一个完整平台项目，原样还原版本链、稳定对象 ID 与冻结脚本。适用于平台库丢失、迁移实例或接管已有库。
- **认领（Claim）**：由实例管理员确认将目标库历史记录中的“当前认领实例”切换为本 Dowel 实例。认领后原实例向该库的执行请求会被拒绝，只读漂移检查与历史读取不受影响。

## 版本与迁移 {#versions-and-migrations}

- **工作副本（Working copy）**：项目里正在实时协作编辑、尚未冻结发布的最新模型状态。
- **版本（Version）**：工作副本在发布时刻生成的不可变快照。一个项目的已发布版本按顺序排成一条链。
- **迁移（Migration）**：版本链上相邻两个版本之间的升级（`up`）与回滚（`down`）脚本。迁移在发布时生成并冻结，保证在每个环境执行的脚本完全一致。
- **发布（Publish）**：将当前工作副本保存为链上的下一个不可变版本并冻结其迁移脚本。
- **执行（Apply）**：沿着版本链把一个或多个迁移脚本按顺序应用到目标库（升级或回滚）。
- **漂移（Drift）**：目标库的实际结构与环境当前版本模型不一致的状态，通常由于有人绕过 Dowel 直接修改了数据库结构引起。
- **标记为已执行（Mark as applied）**：不执行任何 SQL，在确认目标库实际结构等于链上指定版本 `X` 的模型后，直接将环境在历史记录里记为已到达版本 `X`。用于漂移后补齐版本、手工处理半途失败的迁移或手工回退。“写入基线”是首次执行时的特例。
- **修复脚本（Repair script）**：Dowel 针对已漂移的环境临时生成的、将目标库结构还原回当前版本模型的 SQL 脚本。仅供查看与复制，Dowel 不会代为执行，也不会写入版本链。
