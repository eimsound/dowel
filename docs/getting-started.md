# 上手指南

Dowel 是一个开源、可自托管的 PostgreSQL schema 建模工具：多人实时在画布上编辑表结构，自动生成迁移脚本，并在影子库里真实执行一遍来验证迁移是否正确、会锁哪些表、会不会重写整表。

> 实验性项目，目前（M1）只支持 PostgreSQL。

## 部署

### Docker Compose（推荐）

```sh
docker compose up -d
```

然后打开 <http://localhost:4600>，用服务启动时打印的一次性初始化令牌创建第一个**实例管理员**（见下方“账户”）。平台数据（用户、项目、版本等）默认存在卷 `dowel-data` 里的 SQLite 文件中；想存到 PostgreSQL，把 `DOWEL_DB` 设为连接串即可（见下方“配置”）。

部署前把 `docker-compose.yml` 里的 `DOWEL_SECRET` 改成一段随机字符串：它用来加密保存的数据库连接信息，之后不能再改。

### 从源码运行

需要 Node.js 26 和 pnpm 12（仓库根目录的 `.tool-versions` 已固定版本，用 mise 可自动安装）。

```sh
pnpm install
pnpm build        # 构建前端
pnpm start        # 启动服务：http://localhost:4600
```

开发时用 `pnpm dev`：服务端（4600）和前端开发服务器（5173，自动转发接口）同时启动，打开 <http://localhost:5173>。

### 配置

| 环境变量                                        | 默认值            | 说明                                                                                                                                                                                 |
| ----------------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `PORT`                                          | `4600`            | 服务端口（接口、WebSocket、前端页面共用）                                                                                                                                            |
| `DOWEL_DB`                                      | `./data/dowel.db` | 平台数据库：默认 SQLite，值为数据库文件路径（目录不存在时自动创建）；`postgres://…` 连接 PostgreSQL；`:memory:` 为内存库（重启即丢失）                                               |
| `DOWEL_WEB`                                     | `apps/web/dist`   | 前端构建产物所在目录                                                                                                                                                                 |
| `DOWEL_SECRET`                                  | 无                | 加密数据库连接信息的主密钥（至少 16 个字符）。不设置时不能添加环境                                                                                                                   |
| `DOWEL_TRUST_PROXY`                             | 无                | 部署在可信反向代理后时设为 `1` / `true`，才会读取 `X-Forwarded-For`（取最后一个地址）、`X-Forwarded-Proto` 和 `X-Forwarded-Host`。不设置时一律使用连接地址，避免客户端伪造 IP / 协议 |
| `DOWEL_PUBLIC_URL`                              | 无                | 对外访问地址，例如 `https://dowel.example.com`。设置后 Origin 校验以它的协议 + host 为准（优先于转发头）；反向代理部署时建议同时设置                                                 |
| `DOWEL_ADMIN_USERNAME` / `DOWEL_ADMIN_PASSWORD` | 无                | 无人值守初始化：实例里还没有用户时，用这两个值直接创建实例管理员（显示名与用户名相同）。适合容器化部署，省掉手动输入初始化令牌                                                       |
| `DOWEL_ALLOW_PASSWORD_LOGIN`                    | 无                | 设为 `1` / `true` 时强制允许密码登录。实例管理员在设置里关掉密码登录（只在配置了 OIDC 提供方之后才允许）后，这是应急入口                                                             |
| `DOWEL_LOGIN_LIMIT`                             | `10`              | 登录失败限速：同一 IP + 账号在窗口内允许的尝试次数（单副本进程内计数，HA 多副本部署下实际总配额约为设定值 × 副本数）                                                                 |
| `DOWEL_LOGIN_IP_LIMIT`                          | `30`              | 登录失败限速：同一 IP 在窗口内允许的总尝试次数，反向代理 / 公司 NAT 后多人共用 IP 时可调大（单副本进程内计数，HA 多副本部署下实际总配额约为设定值 × 副本数）                         |
| `DOWEL_LOGIN_WINDOW_MS`                         | `600000`          | 登录失败限速的窗口长度（毫秒），默认 10 分钟（单副本进程内计数，HA 多副本部署下实际总配额约为设定值 × 副本数）                                                                       |
| `DOWEL_CONNECTION_LIMIT`                        | `10`              | 连库探测限速：同一用户在窗口内允许的连接检查 / 接手探测 / 漂移检查 / 读历史次数（单副本进程内计数，HA 多副本部署下实际总配额约为设定值 × 副本数）                                    |
| `DOWEL_CONNECTION_WINDOW_MS`                    | `60000`           | 连库探测限速的窗口长度（毫秒），默认 1 分钟（单副本进程内计数，HA 多副本部署下实际总配额约为设定值 × 副本数）                                                                        |
| `DOWEL_TOKEN_FAIL_LIMIT`                        | `20`              | CI 令牌认证失败限速：同一 IP 在窗口内允许的认证失败次数（单副本进程内计数，HA 多副本部署下实际总配额约为设定值 × 副本数）                                                            |
| `DOWEL_TOKEN_FAIL_WINDOW_MS`                    | `600000`          | CI 令牌认证失败限速的窗口长度（毫秒），默认 10 分钟（单副本进程内计数，HA 多副本部署下实际总配额约为设定值 × 副本数）                                                                |
| `DOWEL_TOKEN_RATE_LIMIT`                        | `120`             | CI 令牌请求速率限速：单个令牌在窗口内允许的请求次数（单副本进程内计数，HA 多副本部署下实际总配额约为设定值 × 副本数）                                                                |
| `DOWEL_TOKEN_RATE_WINDOW_MS`                    | `60000`           | CI 令牌请求速率限速的窗口长度（毫秒），默认 1 分钟（单副本进程内计数，HA 多副本部署下实际总配额约为设定值 × 副本数）                                                                 |
| `DOWEL_DRIFT_INTERVAL_MINUTES`                  | `60`              | 定时漂移检查的间隔（分钟），逐个环境读目标库结构并与当前版本比较；`0` 关闭。见 [执行迁移、回滚与漂移](execution.md)                                                                  |

### `connection_allowlist`（允许连接哪些地址）

服务端会主动去连用户填的数据库地址（连接检查、建环境、导入结构），所以实例管理员可以在“管理后台 → 实例设置”里限制能连到哪里：

- 一项一行（或逗号分隔），可以是 **CIDR**（`10.0.0.0/8`、`2001:db8::/32`）、**单个 IP** 或 **主机名**（`db.internal`）。
- 主机名先解析成 IP 再比对，所以 `localhost`、`127.0.0.1`、`::1` 需要分别写（或写成 `127.0.0.0/8`、`::1/128`）。
- **留空表示不限制**（自托管默认）。填了以后只允许列表里的地址；不在列表里时连接检查返回 422，建环境同样被拒绝。
- 连接检查按用户限速（每分钟 10 次，向导里每个环境、每次导入各算一次），避免服务端被当成端口扫描器。
- 为了让白名单说了算，**连接串里只能用 URL 的 authority 指定主机**：`?host=` / `?hostaddr=` 参数（它们会覆盖主机名）和 unix socket（`/var/run/postgresql`）都会被拒绝，多主机（逗号分隔）则逐个检查。

## 使用

1. **初始化、登录、新建组和项目。** 第一次启动时服务日志里会打印一次性初始化令牌，用它在 `/setup` 创建第一个实例管理员；也可以设置 `DOWEL_ADMIN_USERNAME` / `DOWEL_ADMIN_PASSWORD` 让服务自己建。之后用**用户名 + 密码**登录。项目属于一个**组**（URL 是 `/project/<组>/<项目>`），所以先建组，再在组里建项目。
2. **新建项目（四步向导）。** 在“我的项目”点“新建项目”（或按 ⌘K 选“新建项目”），地址是 `/new`：
   - **基本信息**：组、项目名、标识（由名字自动生成，可以改）；
   - **关联数据库**（可以跳过）：添加一个或多个环境（目标库），每个都能“检查连接”，显示 PostgreSQL 版本、当前用户、是否超级用户、能否建库 / 建 schema，以及每个 schema 有多少张表；
   - **初始内容**：空白（只有一个空的 `public` schema）/ 从数据库导入（选一个环境，勾选要导入的 schema，默认全选）/ 从 SQL 导入（粘贴或选择 `.sql` 文件）/ **接手现有项目**（目标库的 `dowel` 历史里已经有项目，见下面“接手现有项目”）；
   - **确认**：汇总后创建。导入完成后自动发布 `v0 · 基线` 版本；**这一步只写 Dowel 平台库，不会修改你的数据库**。

   导入只读目标库：Dowel 只执行 `SET` 和 `SELECT`，所以**只读账号就够了**（见下方“导入需要的数据库权限”）。从 SQL 导入还需要一个能建影子库的账号（或事先配好一个空库作影子库）。
3. **选择 schema 范围（可选）。** 项目设置里的“schema 范围”决定导入、从环境拉取和规范化看哪些 schema；不选表示全部，`dowel`（Dowel 自己在目标库里的迁移历史 schema）永远跳过。
4. **连接你的数据库。** 点“环境”，添加项目要部署到的数据库（例如开发库、预发库）。之后：
   - 可以“从此库导入结构”；
   - 迁移会在这个实例上的影子库 `{原库名}_dowel` 里验证：版本、扩展、排序规则都与目标一致。有建库权限时 Dowel 自动创建它，没有时会提示要执行的语句；
   - 标记为“生产环境”的库默认不在同一实例上建影子库（检查会占用实例资源），需要明确允许，或另外指定一个空库作影子库；
   - Dowel 只会清空它自己建的、或你指定且原本为空的影子库（库上有 Dowel 的标记），不会动其他库。

   **导入 SQL、验证迁移都需要至少一个环境**：Dowel 只用真实的 PostgreSQL 实例作影子库，没有可用的影子库时会直接报错。

### 导入需要的数据库权限

导入只读结构，Dowel 需要的权限很少：

| 用途                                    | 需要的权限                                                                                                             |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 从目标库导入（向导 / “从此库导入结构”） | `CONNECT` 到该库 + 相关 schema 的 `USAGE` + 表的 `SELECT`（读系统目录不需要额外授权）；`dowel` schema 里的东西不会被读 |
| 显示 schema 列表、能否建 schema         | 同上（用自己的账号查 `pg_namespace` / `has_database_privilege`）                                                       |
| 从 SQL 导入（影子库）                   | 目标账号的 `CREATEDB`（自动建 `{原库名}_dowel`），或者另外配一个空库作影子库                                           |

**只读账号就足够导入**：Dowel 只会执行 `SET` 和 `SELECT`，导入前后目标库的结构完全不变，也不会建 `dowel` schema（第一次把迁移执行到该库时才建）。

### 影子库的账号与安全边界

影子库是 Dowel 真的**执行**你的迁移脚本、导入的 SQL 的地方，所以它值得单独一小节：

- **影子库最好和线上库不在同一个实例上，或者用一个独立的低权限账号。** 在“环境”里可以为每个环境另外指定影子库的连接串（和目标库的账号分开）：这个账号只需要能在影子库里建表、删表（它自己的库的所有者），**不要给 `SUPERUSER` 或 `CREATEROLE`**；同实例的 `{原库名}_dowel` 由有 `CREATEDB` 的账号建好后，也建议交给这个低权限账号所有。
- **生产环境默认不在同一实例上建影子库**，需要明确允许，或者另外配一个影子库实例（上面已经说过）。
- Dowel 会拒绝迁移脚本和导入的 SQL 里的**实例级语句**——`CREATE / DROP / ALTER DATABASE`、`TABLESPACE`、`ROLE | USER | GROUP`，以及 `ALTER SYSTEM`——因为它们作用于整个数据库实例，而不只是这个库。这只是防止误操作的检查，**不是安全边界**：写在 `DO` 块或函数里用 `EXECUTE` 拼出来的动态 SQL 它看不出来。真正的边界是上面两条：影子库账号的权限，以及生产环境不和影子库放在同一个实例上。

5. **导入现有结构（可选）。** 可以在“环境”里“从此库导入结构”；也可以点“导入 SQL”，粘贴或选择 `pg_dump --schema-only` 的输出。Dowel 会在影子库里执行它并读出结构，支持表、约束、索引、枚举、序列、identity、生成列、分区表，以及视图、函数、触发器、域、聚合等对象和常用扩展（pgvector、pg_trgm、uuid-ossp、citext、hstore 等）。
6. **编辑。** 在画布上拖动表，在右侧面板编辑表名、列（类型、非空、主键、默认值、顺序）、CHECK、唯一约束、外键和索引。改列名时，引用它的约束名和表达式会自动跟着改。表达式（CHECK、默认值等）保存后会换成 PostgreSQL 的规范写法，例如 `price > 0` 会显示为 `(price > (0)::numeric)`，这样与数据库里读出的结构可以直接比较。
7. **保存版本。** 点“保存版本”给当前状态起个名字，作为生成迁移的起点和终点。
8. **生成并验证迁移。** 点“迁移”，选择“从”和“到”两个版本，即可看到升级和回滚脚本。点“在影子库验证”，Dowel 会：

- 在影子库里执行升级脚本，检查结果与目标版本完全一致；再执行回滚脚本，检查能回到原版本；
- 逐步测量每条语句拿了什么锁、是否重写整表、是否全表扫描，标出高 / 中 / 低风险。

9. **下载 `.sql`。** 下载的脚本开头带有固定的会话设置（时区、日期格式、`search_path` 等），保证在任何连接上执行结果都相同。
10. **执行到环境。** 发布并验证通过的版本，可以在“环境”详情页**执行**到目标库、也可以**回滚**；确认对话框会先**预演**一遍（只检查、列出要做的事，不写任何东西）。Dowel 会先做完整性、漂移检查，逐个迁移执行并读回结构校验，历史写在目标库的 `dowel` schema 里。生产环境需要输入环境名确认，谁能执行由环境上的一档设置决定（非生产默认项目编辑者，生产默认项目管理员）。详见 [执行迁移、回滚与漂移](execution.md)。

## 接手现有项目

目标库的 `dowel` schema 里存着每个版本的完整模型（含对象 ID）和冻结脚本，所以**只要目标库在，Dowel 就能重新接手它的项目**——换了一个 Dowel 实例、平台库丢了、或者同一个库被另一个实例写过。

### 向导里怎么做

在新建项目向导里初始内容选“**接手现有项目**”：

1. **给连接串。** 可以一次给**多个环境**（比如 dev 和 prod）；每个环境都必须是这个项目的目标库。Dowel 只读地检查每个库，列出 `dowel.projects` 里**登记过的项目**（名字、版本数、最新版本和当前版本、最近一次执行、由哪个实例认领）。
2. **选一个项目。** Dowel 新建一个平台项目，**项目 ID 沿用目标库里的项目 ID**（目标库里的历史按项目 ID 存，不沿用就接不上）。本实例里已经有同一个项目 ID 时不能接手（要给它加环境请用下面的“添加环境并接入已有历史”）。
3. **认领（如果需要）。** 库里的项目由**另一个实例**认领时，必须由**实例管理员**确认“认领”：确认对话框会说明后果——原实例之后执行这些库会被拒绝；只读的漂移检查和读历史不受影响。不是实例管理员的组成员只能接手没有被别的实例认领的库。库里认领它的就是本实例（比如项目被删了、平台库还在）时不需要确认。
4. **创建。** 接手相当于新建项目，要求你在目标组里有建项目的权限。

### 恢复什么

- **完整的版本链**，原样恢复：版本 ID、序号、父版本、名字、**完整的模型（对象 ID 原样保留）**、冻结的升级 / 回滚脚本、`checksum`、冻结时的 **schema 范围**、发布时间。所以接手之后改列名，冻结出来的仍然是 `RENAME COLUMN`，不是先删后加。
- **工作副本 = 链头版本的模型**；项目的 schema 范围 = 链头版本的范围。
- **每个环境的当前版本 = 它的目标库历史里最后完成的版本**；各环境执行过哪些版本、版本的“已执行”标记也按各自的历史写上（执行过的版本不能再编辑脚本）。
- 接手之后 Dowel 对每个环境做一次漂移检查，环境页能马上看到结果。**接手本身不处理漂移**：它只认领、恢复版本链和当前版本；接手之后线上结构和当前版本对不上的，就是普通的漂移，按 [执行迁移、回滚与漂移](execution.md) 里的两个出口处理（保留线上的修改 / 放弃线上的修改 / 标记为已执行）。
- **认领放在平台库写完之后**：项目先建好，再去目标库认领（并在目标库的项目锁里重新比对版本链）。如果某个库认领失败——或者读取之后原实例又往前执行了新版本，历史已经领先于接手出来的链——项目照样保留，结果里给出警告；前一种情况可以在环境页重试认领，后一种需要删除这个项目后重新接手。
- 接手检查里，本实例已经有同一个项目 ID 的库会标为“已存在”，不能重复接手；如果那个项目你看不到，只提示“已存在，请联系管理员”，不给名字和归属。

### 接手前强制影子库验证

写入平台前，Dowel 会用本实例的影子库按版本顺序（`v0 → v1 → … → vN`）对合并后的**整条历史链**做闭环验证：

- 向导支持为每个环境填写独立影子库连接串，或勾选「允许在同一实例上建影子库」（生产环境默认不在同实例建影子库）。
- 找不到可用影子库，或链上任意一个版本验证不通过时，**直接拒绝接手**（不写平台库，也不认领目标库），并指明失败的版本号与原因。
- 全部验证通过后，恢复进入平台的每个版本都会写入 `verified_at` 与验证报告（同时保留“接手恢复”来源标记），可直接执行或回滚，无需再手工逐个重新验证。

### 什么时候拒绝接手

恢复前 Dowel 先做校验，**不通过就拒绝，什么都不建、也不认领**，并说明原因：

- 每个环境自己的历史必须完整：序号连续、`parent` 衔接，**每个版本的冻结脚本按内容重算的校验和等于记录值**（篡改了校验和或脚本会被发现）；
- **同一个版本 ID 在各环境里的内容必须一致**（校验和、模型、序号、父版本、名字、schema 范围）；
- **链不能分叉**（两个环境在同一个父版本下有不同的子版本，或者起点不同）；
- 环境的库里**没有**这个项目的历史；
- 历史的**格式比当前 Dowel 新**（需要先升级 Dowel）；
- **没有可用的影子库**，或整条历史链上**任意一个版本在影子库闭环验证失败**。

### 多环境合并规则

各环境的历史**按版本 ID 合并成同一条链**。同一个版本 ID 的内容必须一致；链分叉就报错，不合并。**一个环境落后、另一个领先是允许的**：链取最长的那条，每个环境各自记录自己的当前版本。例如 dev 在 v3、prod 在 v2，接手后链是 v1～v3，dev 的当前版本是 v3、prod 是 v2，v3 对 prod 是“待执行”。

### 给已有项目添加环境并接入已有历史

已有的项目也可以“**添加环境并接入已有历史**”：新环境的库里已经有这个项目的历史（比如从生产库恢复出来的备份、另一个实例写过的库）时，Dowel 把它接进来，当前版本和执行过的版本按这份历史同步。

- 这是**特权操作**：至少要项目管理员，并且要满足这个环境的执行档位（和改连接串、删环境同一套规则）。
- 这份历史必须和平台上的版本链**一致**（每个版本的 ID、序号、父版本、校验和、模型和 schema 范围都一致），或者是平台链的**严格领先延伸**（包含平台链的全部版本且末尾多出 1 个或多个连续延伸版本，无分叉）；若存在分叉或任一已有版本不一致则拒绝。
- **目标库严格领先于平台链时**：
  1. Dowel 先按顺序在影子库里对全部领先版本做闭环验证（基线模型为原链头模型）；找不到可用影子库或任一版本验证失败，直接拒绝接入（不写平台库，也不认领目标库）。
  2. 全部领先版本验证通过后，补齐平台版本链（带验证报告和“接手恢复”标记），并把工作副本更新到新链头。如果当前工作副本存在未发布的修改，接入前会先展示覆盖画布前后的差异对比和领先版本列表，经你确认后再覆盖（覆盖前的草稿保留在画布修改历史中，随时可查看或恢复）。
- 库里没有这个项目的历史时，它只是一个普通的新环境。
- 库里的项目由另一个实例认领时，需要**实例管理员确认认领**（否则拒绝）。
- 已经添加的环境，如果它的库被另一个实例认领了，实例管理员可以在**环境详情页**点“认领”。
- **环境行先建好，认领在提交之后**：认领失败（比如账号没有写 `dowel` 的权限）时环境照样保留，结果里有警告，可以改好连接账号后在环境页重试认领；同步目标库状态失败也只是警告，不影响接入结果。认领前同样会在目标库的项目锁里拿最新合并后的版本链重新比对。

### 灾难恢复：目标库在，Dowel 就能接手

平台库丢了（磁盘坏了、没有备份），或者 Dowel 重装、`instance_id` 变了——只要目标库还在：

1. **装好新实例并初始化**（`/setup` 创建第一个实例管理员，配好 `DOWEL_SECRET`；如果沿用旧的 `DOWEL_SECRET` 也行，但连接串是新输的，不依赖它）。
2. **实例管理员新建项目，选“接手现有项目”**，给出**所有环境**（dev、staging、prod……）的连接串，并为至少一个环境配好独立影子库连接串（或允许同实例影子库）；Dowel 列出每个库里登记过的项目，选中要恢复的那一个。
3. **确认认领。** 库里记着的认领者是旧实例（重装后的同一个实例也是“另一个实例”，因为实例标识变了），确认后 Dowel 会先在影子库验证整条版本链，全部通过后写入平台库并认领目标库；旧实例如果还活着，之后执行会被拒绝。
4. **检查结果**：项目、已验证的版本链（版本号、对象）、每个环境的当前版本、漂移状态。
5. **继续发布**新版本、执行。

**会丢的**：平台库里不在目标库里的东西——工作副本里**未发布的修改**、画布布局、成员与授权（接手人成为项目管理员，其他人要重新授权）、审计日志、项目设置里的其他配置、各环境的“谁能执行”档位和生产标记（接手时按向导里填的重新设置）。`DOWEL_SECRET` 丢了的话，旧的密文连接串无法解密，接手时重新填连接串即可。**不会丢的**：所有**已发布的版本**（模型、对象 ID、冻结脚本）和**目标库里的执行历史**。同一个实例装回去（平台库没丢，只是项目被删了）也走同一套，此时认领者就是本实例，不需要确认认领。

## 账户

- **一个实例只服务一家公司。** 术语见仓库根目录的 `GLOSSARY.md`：实例、用户、实例管理员。
- **用户名 + 密码登录。** 用户名由小写字母、数字和 `-` 组成，1～39 位，全实例唯一，可以改（在个人设置里）。邮箱选填、不唯一、不验证，不用于登录或找回密码。
- **注册仅限邀请。** 实例管理员可以直接建用户，或生成一次性邀请链接（`/invite/<令牌>`，默认 7 天有效）。接受邀请时自己设置用户名和密码。
- **重置密码**由实例管理员生成一次性链接（`/reset/<令牌>`，24 小时有效），设完新密码后这个用户的所有会话都会失效。
- **停用用户**会立即删掉他的会话并断开他的 WebSocket。最后一个启用的实例管理员不能被停用或降级。
- 实例管理员还能改实例名称、是否允许密码登录；**没有任何 OIDC 提供方时不允许关闭密码登录**，避免把所有人锁在外面。此时可以用 `DOWEL_ALLOW_PASSWORD_LOGIN=1` 应急。

## 配置 OIDC 登录

Dowel 支持通用的 OpenID Connect（授权码 + PKCE）。实例管理员配置好提供方后，登录页会出现“使用 XX 登录”，邀请页也可以直接用外部账户接受邀请。密码登录仍然可用；只有至少有一个启用的提供方时，才允许在实例设置里关闭密码登录。

### 前置条件

- 设置 `DOWEL_SECRET`（至少 16 个字符的随机字符串）：OIDC 的 `client_secret` 用它加密后存在平台库里，列表接口只返回“是否已设置”。换掉这个值后旧密文无法解密，需要重新填一次 client secret。
- 尽量设置 `DOWEL_PUBLIC_URL`（例如 `https://dowel.example.com`）：OIDC 回调地址用它推导。没设置时会按请求的协议 + Host（在可信反向代理后按 `X-Forwarded-*`）推导；如果代理配置不一致，回调地址就可能和提供方里登记的不一样。反向代理部署建议同时设置 `DOWEL_PUBLIC_URL` 和 `DOWEL_TRUST_PROXY=1`。

### 回调地址的格式

```
{DOWEL_PUBLIC_URL}/api/auth/oidc/{slug}/callback
```

`slug` 是创建提供方时填的标识，例如 `google`、`gitlab`、`corp-sso`。在提供方的控制台里把“授权回调 / Redirect URI”登记成这个地址。一个提供方对应一个 slug。

### Google

1. 在 Google Cloud Console 创建 OAuth 2.0 Client（类型 Web application）。
2. Authorized redirect URI 填 `https://你的域名/api/auth/oidc/google/callback`。
3. 记下 Client ID 和 Client secret。
4. 在 Dowel 里用接口创建提供方（管理界面在 P2）：

```sh
curl -X POST https://你的域名/api/admin/oidc \
  -H 'content-type: application/json' \
  -b 'dowel_session=…' \
  -d '{"slug":"google","name":"Google","issuer":"https://accounts.google.com",
       "clientId":"…","clientSecret":"…","scopes":"openid profile email"}'
```

保存时 Dowel 会做一次 `.well-known/openid-configuration`；配错会直接返回 422 和原因。`GET /api/admin/oidc/presets` 里有 Google / GitLab 的 issuer、文档链接和建议的 scopes。

### GitLab

1. 在 GitLab（gitlab.com 或自建实例）的 Admin / Applications（或用户设置里的 Applications）新建 OAuth 应用。
2. Redirect URI 填 `https://你的域名/api/auth/oidc/gitlab/callback`。
3. Scopes 勾选 `openid`、`profile`、`email`。
4. 创建提供方时 issuer 用 `https://gitlab.com`；自建 GitLab 改成 `https://gitlab.example.com`。
5. 想允许未被邀请的人自动开户时，创建 / 修改提供方时把 `autoProvision` 设为 `true`；默认关闭，未邀请的账户会被拒绝。

### 个人关联

已经登录的用户可以走 `GET /api/auth/oidc/{slug}/start?mode=link` 把外部身份关联到当前账户；`GET /api/me/identities` 列出已关联的身份，`DELETE /api/me/identities/{id}` 解除关联。解除最后一个登录方式（没有密码、也没有其他身份）会被拒绝（422）。

## 组、权限与多人协作

- **组**是一群用户，可以拥有项目。组、组成员和组管理员对所有已登录用户可见；**组的项目只对有权限的人可见**，看不到的项目在列表、搜索、链接和实时协作里一律当作不存在。
- 建组默认为所有用户开放（实例管理员可以在实例设置里改成“只有实例管理员能建”）；建组的人成为组管理员。组里还有项目时不能删组。
- 组管理员管理组成员和组设置，也能在组里建项目（可以改成只有组管理员能建项目）。
- **项目角色**分查看者、编辑者、项目管理员。一个用户对项目的最终角色，取下面几项里最高的：实例管理员；项目所属组的组管理员；组成员按组的**默认权限**（每个组一个默认值，组管理员可以为单个项目另设）；以及**授权**。
- **授权**把一个角色授给一个用户或一个组，范围可以是某个项目、某个组的全部项目，或者整个实例。项目管理员管项目级授权，组管理员管组级授权，实例管理员管实例级授权。项目至少要有一个人是项目管理员；组里至少要有一个人是组管理员（实例管理员不受这条限制）。
- 项目的“成员与授权”对话框里，直接授权和“来自组默认权限的成员”分开显示；可以添加用户或组、改角色、移除授权，也可以修改项目的默认权限、把项目转到另一个组（需要同时是两个组的组管理员，旧地址会自动跳转）。
- 邀请链接可以带上组：接受邀请后直接成为这些组的成员。
- 角色变动**即时生效**：在线连接会自动切成只读或被断开，不需要刷新页面。
- 所有人的修改实时同步。
- **先到先得**：如果你在编辑某个对象（例如正在改表名、写 CHECK 表达式）期间，别人已经改了它或它引用的列，你保存时会被拒绝，并提示是谁改的；页面会显示最新的内容，你可以在此基础上重新修改。

## 当前的限制

- 只支持 PostgreSQL。导入 SQL、验证迁移需要先配置环境（真实的 PostgreSQL 实例）。
- 可以在环境详情页把版本**执行 / 回滚**到你的数据库，并检查漂移，见 [执行迁移、回滚与漂移](execution.md)。审批和执行申请、CI 令牌还没有；仍然可以下载 `.sql` 自行执行。
- 分区表可以导入和查看，不能修改结构。
- 视图、函数、触发器等对象只能通过导入修改；给它们引用的列、表改名时，Dowel 会自动更新它们的定义。
- SQL 视图是只读的。
- 枚举值可以新增；删除或重排已有的值会重建枚举类型（迁移脚本会自动处理）。
