# 接手与接入领先环境强制影子库验证；接入领先环境带差异确认覆盖工作副本

2026-11-21 决定（P6.5，修订 P4c 原取舍）：所有从外部目标库恢复进入平台的冻结版本（无论是新建项目**接手**整条历史链，还是已有项目**接入**严格领先于平台链的目标库）都必须在写入平台前经本实例影子库闭环验证通过；缺少可用影子库或任一版本验证失败时直接拒绝并指明具体版本与原因，平台内不再产生「未验证的恢复版本」，因此也无需提供「批量重新验证」功能。

- **接手向导配套**：允许在接手向导中为每个环境配置独立影子库连接串或勾选允许同实例影子库。
- **接入领先环境与工作副本**：当目标库历史是平台链的严格延伸（无分叉）且领先版本全部通过影子库验证后，补齐平台版本链并**覆盖工作副本到新链头**。若当前工作副本不是链上版本（存在未发布草稿），接入流程必须先展示覆盖画布前后的差异对比并经用户确认；如需回看或找回被覆盖前的草稿，通过模型页基于 `room_snapshots` + `room_commits` 的「画布修改历史」（支持查看单次变更、当时模型状态、与当前画布差异，及一键恢复到此状态）完成。
- **不做「撤销认领」**：认领交还统一由原实例的实例管理员主动反向认领，避免单方面把认领权退回给版本链已落后的旧实例。

## Considered Options

- **接手不强制验证，恢复后逐个或批量重新验证**（P4c 原实现）：无影子库或历史老版本失效时也能先接手项目，但打破了「平台内所有待执行冻结版本均经本实例影子库验证」的不变式，且恢复后体验割裂。
- **接入领先环境时保留脏工作副本不动，仅弹警告**：容易导致用户忘记对齐画布，下一次发布时意外把新链头新增的对象删掉；改为先看差异确认覆盖 + 在线文档式修改历史兜底，兼顾安全与直觉。

> **2026-11-27 补充（见 [ADR 0017](0017-verified-means-executable.md)，Issue #132）**：接手与接入领先环境时的闭环验证包含读回核对（影子库读回的结构必须与版本模型一致），验证结果按影子库的数据库完整版本号记录；恢复进来的版本要执行到某个环境，同样要求在版本一致的影子库上验证通过。不为修复前产生的旧数据保留兼容路径。
