# MCP 与画布编辑：个人令牌、正交 scope、绝不连目标库；AI 只改工作副本，一次调用一条原子历史

- **状态**：已生效（Implemented）
- **领域 / 范围**：内置 MCP 服务（`POST /api/mcp`）的身份、权限、安全边界与传输；CI 接口的 OpenAPI 文档；AI 经 MCP 修改画布的能力（板块、复合宏、`batch`、写后自检、只读上下文、Prompts）；人类连续编辑的画布历史降噪
- **合并自**：原 ADR 0014（2026-11-24，M3-C，落实 Q26）、原 ADR 0015（2026-11-26；PR #117、#119、#120、#121、#122）；界面规格 `.agents/docs/ui/mcp-tokens.md`；用户文档 `docs/{zh,en}/mcp.md`
- **重审触发条件**：要支持 OAuth 2.1 一键登录（`mcp_tokens.kind` 已预留）；要让 AI 发布版本、提交执行申请或读取目标库实时状态；要在平台本体内置 LLM

Dowel **不在平台本体内置 LLM**。AI 能力聚焦外部 AI 编程助手经内置 MCP 服务修改画布；AI 的修改走与人相同的同步层冲突规则与评审，不开后门。两条安全红线贯穿全文：**绝不连接目标库**；**不能发布版本，也不能提交、审批或执行迁移**。

## 1. 身份：MCP 令牌属于用户，不属于项目

- 明文 `dwm_` + 32 字节随机数（base64url），库里只存 SHA-256（理由同 [05-ci-tokens-and-api.md](05-ci-tokens-and-api.md) 第 1 节）。
- 每个请求实时计算权限 = 用户**当前**生效项目角色 ∩ 令牌 scope ∩ 可选项目白名单；降权、移出组立即生效。
- 修改和审计都记在本人名下并带 MCP 标记，画布修改历史显示本人。
- 所有活跃用户都能在个人设置自助签发，不复用 CI 令牌的三层创建规则；实例设置“允许 MCP 访问”（默认开）是总开关，关闭后不能新建、已有令牌一律 `403 mcp_disabled`（不删除）。实例管理员可查看并吊销任意用户的 MCP 令牌。
- **与 [02-consensus.md](../02-consensus.md) 11.4“不做个人令牌”的关系**：那条只针对 CI（流水线凭据应当随项目、不随人，离职不影响流水线）。MCP 的使用者是坐在终端前的人，AI 代表本人工作，权限和责任应当跟人走；CI 仍然只有项目级令牌。

## 2. scope 正交、只能收窄，令牌必须过期

- `read` 是基线（总是包含）：项目、模型、DDL、版本链、迁移预览、环境的平台缓存状态。
- `verify` 只授权影子库验证（等同界面的验证权限）。
- `write` 只授权工作副本的修改（还要求项目编辑者以上）。
- `verify` 与 `write` 可独立勾选，都隐含 `read`。令牌必须过期（默认 30 天、最长 1 年，没有永不过期），每个用户的有效令牌数有上限。

## 3. 写边界：只有工作副本与影子库

- MCP 的每个写操作最终都是 `@dowel/core` 的 mutator，走与 WebSocket 编辑完全相同的路径：分支行锁 + 追赶外部提交、`reads` 冲突检测（以 AI 读取时的 `baseSeq` 为依据，之后被别人改过或删掉的对象一律冲突）、实时广播给在线协作者、画布修改历史可一键恢复。
- 整批原子：先在写时复制的副本上把整批预执行一遍，任何一步会被拒绝就整批不提交；支持 `dryRun`；新对象用 `$ref:<alias>` 由服务端生成 UUIDv7。
- MCP 客户端标识与 WebSocket 客户端、`system` 在结构上不相交。

## 4. 硬边界、隔离、吊销与限流

- **绝不连目标库**：环境状态与漂移只读平台缓存（带缓存时间与来源标记），MCP 代码不调用任何目标库连接（读历史、实时漂移、执行器）。影子库验证可以连影子库（含同实例影子库），这是界面既有能力，不碰目标库的结构与历史。
- **不开放**：发布版本、提交执行申请、执行 / 回滚 / 紧急执行 / 标记为已执行 / 接入 / 认领 / 审批、改连接串或执行策略、整库导入覆盖、恢复画布历史。发布和执行始终由人在界面上完成，走原有审批流程。
- **双向隔离**：`Bearer dwl_…` 只能访问 `/api/ci/…`，`Bearer dwm_…` 只能访问 `/api/mcp`，越界一律 403、不回落 Cookie；`/api/mcp` 只认 MCP 令牌，会话 Cookie 与 CI 令牌都不接受。
- **吊销**：用户被停用、管理员重置密码、使用重置密码链接时**永久吊销**该用户的全部 MCP 令牌（与吊销会话一致，并跨副本清缓存）；删除用户级联删除；自己改密码不吊销；处于强制改密期间请求实时 `403 password_change_required`。
- **限流**：认证失败按来源 IP 限速并配活跃令牌快照防误杀；每令牌单独限速；影子库验证另受按用户计的连接限速（防多建令牌绕过）。HA 多副本下限流按副本计数（[01-org-and-deployment.md](01-org-and-deployment.md) 第 2 节）。

## 5. 传输：官方 SDK 的无状态 handler

用官方 `@modelcontextprotocol/server` SDK 的无状态 handler：同时服务新版逐请求协议与旧代客户端的无状态回退；不发会话 ID、不开 SSE（GET / DELETE 返回 405），多副本无需粘性路由。工具输入 schema 直接由 zod 生成。依赖选型须满足仓库的最短发布期与来源证明（provenance）策略。

## 6. OpenAPI 只给 CI 接口

把 7 个对外 CI REST 接口放进独立的 OpenAPI 子应用，生成 `GET /api/ci/openapi.json`（OpenAPI 3.1）与 `GET /api/ci/docs`（交互文档）；主应用和约 100 个内部接口不动。两个文档端点接受有效会话（已完成强制改密）或有效 CI 令牌，匿名 401、MCP 令牌 403；7 个业务端点仍只认 CI 令牌。文档页的脚本由 web 构建打包到同源，页面无内联脚本，不放宽全局 CSP `script-src 'self'`，不加载外部 CDN。

## 7. 画布布局：开放板块（Section）读写，不开放像素坐标

- 像素坐标继续由前端自动排布与人工拖拽管理，MCP 不暴露坐标写接口，避免 LLM 二维排版重叠或制造布局并发噪音。
- 板块读写归入 `write` scope（且要求项目编辑者以上），不新增 scope。
- 只提供**增量**语义操作（建、改名、改色、删板块，把表加入 / 移出板块；单表移入新板块时自动从旧板块迁出，保持“一张表至多属于一个板块”的不变式），由服务端在房间锁内基于最新板块合并、落库、审计并实时广播，避免并发协作时全量替换误抹同事新建的板块。读模型时同步返回板块与每张表的归属。

## 8. 复合宏：在原子批次内编译展开，不做整表 diff 与 SQL 反解析

- 在保留全部底层 mutator 的前提下，批量修改的输入层支持两个**编译型复合宏**，由服务端在预演阶段展开为标准底层 mutator，可与底层操作混排在同一批原子提交中：
  - **`defineTable`**：一次声明建表 + 列 + 主键 / 唯一 / CHECK / 外键 / 索引 + 注释 + 扩展属性 + 可选分区；本表约束与索引可按列名引用本批新建列。
  - **`alterColumn`**：声明式 patch 修改已有列（省略即不改，`null` 显式清除），按固定安全顺序展开，消除互斥约束的顺序冲突。
- 输入条数与展开后的底层子操作数各有上限；验证或冲突报错映射回外层输入下标与子路径。
- **稳定对象 ID 底线**：修改与删除既有对象（含 `alterColumn` 指向的列）严格要求对象 ID，绝不按名猜测或做整表期望状态 diff，确保改名不断链与并发精确判冲。唯一的名称解析例外是**引用槽位**（新建对象引用的 schema、类型、外键目标、序列、本表列名等），允许按（限定）名称解析到既有对象，不存在或重名时报明确错误；被修改或删除的对象本身永远不按名称定位。

## 9. 一次 MCP 修改 = 一个 `seq` = 一条原子历史

- `@dowel/core` 提供受控原子批处理 mutator `batch`（`{ ops, summary? }`），与 `paste` 同构：只允许常规白名单 mutator，禁止嵌套 `batch` 与 `paste`，有最大展开子操作数；不在 mutator 列表里暴露给 AI。
- 服务端在房间锁内预演并合并整批外部 `reads` 冲突检测，通过后作为 **1 个 Op / 1 个 `seq` / 1 条 `room_commits` / 1 次广播** 提交，可选 `summary` 写入画布历史与审计。人在画布历史里可查看整批差异，恢复到 `seq - 1` 即整批撤销。
- 响应只返回单个 `seq` 与展开的操作数（附 `refs`、`changed`、`diagnostics`）。Dowel 尚未发布首个公开版本，直接收敛，不保留多 `seq` 兼容。

## 10. 人类连续手工编辑：服务端读时归组

- 底层 `room_commits` 与实时同步 `seq` **零改写**：协作客户端的冲突基准与精确审计依赖真实递增的 `seq`。
- 画布历史列表默认在**读时**把同一用户、非 MCP、连续的普通单步编辑（相邻间隔、单组总跨度与步数都有上限）聚合为一个编辑会话组；分页游标按整组边界对齐，不把一次连续编辑劈成两页；默认展示整组净差异，也可展开组内每一步，按单步或组尾恢复。
- **硬断点**（绝不跨界合并）：换人、已发布版本、`paste`、导入 / 恢复 / 应用版本到画布。
- MCP 只读历史复用同一归组能力（默认归组，可读原始单步）。

## 11. 写后静态自检：沿用画布准入门槛，零往返附带 `diagnostics`

MCP 修改沿用与画布 UI 一致的准入门槛（单步 mutator 合法即提交，允许多步草稿中间态，不被存量校验或兼容性问题阻塞），并在响应（含 `dryRun`）里自动附带完整模型校验错误与基于项目最低目标环境的静态兼容性错误 / 警告。读模型时同步暴露方言能力摘要与推导的目标版本，让 AI 起草前就能预知方言约束。

## 12. 只读上下文、MCP Prompts 与历史恢复红线

- **只读上下文**（`read` scope，零目标库连接）：按关键字 / 板块 / schema 过滤模型、读取枚举 / 序列 / 扩展 / 不透明对象的完整 IR、读取表及其依赖的不透明对象、读取归组后的画布历史与单步 / 整组差异。读模型类工具读前与其他出口一样按需规范化（[07-normalization-and-verification.md](07-normalization-and-verification.md) 第 1 节）；**读画布历史的工具绝不规范化、绝不连影子库或目标库、不写审计**。
- **MCP Prompts**：评审未发布修改、评审画布历史（`read`）与设计表、重构列（仅 `write` 令牌可见）。文案随令牌 scope 生成（有 `verify` 才建议验证），始终声明发布版本、连接 / 执行目标库与恢复画布历史保留给人工。渲染时零数据库查询（不能借 Prompts 探测项目是否存在）；只按本令牌的注册表校验名称，越权名称与原型属性名一律 `InvalidParams`。
- **不开放恢复画布历史的写工具**：整库覆盖式恢复继续由人在界面确认完成；契约测试断言工具列表里永不出现恢复 / 回滚历史、发布版本、执行迁移一类工具。

## 被否决的方案

- **项目级 MCP 令牌（类似 CI 令牌）**：修改记在令牌名下而不是人名下，协作冲突提示与审计失去“谁”；跨项目工作要配 N 个 MCP server；容易与 CI 的免审批执行通道混淆。
- **OAuth 2.1（授权服务器、PKCE、客户端注册、同意页）**：桌面 / 网页连接器能一键登录，但要在 Dowel 里实现完整授权服务器，无浏览器环境不友好；作为以后的扩展暂缓，令牌表预留 `kind`。
- **允许 MCP 实时连目标库读状态 / 检查漂移**：对 AI 有用，但会让 AI 驱动对生产库的连接，SSRF 面和生产库压力不可控；平台缓存（定时漂移检查、执行后同步）已能回答“在哪个版本、有没有漂移”。
- **允许 MCP 发布版本或提交执行申请**：版本链只追加不可删，AI 循环重试容易产生脏版本；执行申请会发收件箱通知与 Webhook，造成噪声。
- **手写 JSON-RPC 处理器（零依赖）**：要自己追两代协议的信封、发现与版本校验，合规风险高；官方 SDK 已不带多余的 HTTP 框架依赖，供应链面可控。
- **全量迁移到 OpenAPI 路由框架**：约 100 个内部接口随界面频繁变化，没有外部消费者，收益低、冲突面大。
- **平台本体内置 LLM 助手**：要维护模型提供商、密钥、配额与提示注入安全面；外部编程助手天然拥有业务代码与 schema 的双重上下文。
- **向 MCP 开放像素坐标写接口或全量替换板块**：LLM 不擅长二维排版；全量覆盖会在并发协作下静默抹掉他人新建的板块。
- **独立的高层写工具、整表期望状态 diff 或任意 SQL 反解析合并**：独立工具无法与底层 mutator 组成单次原子提交与单条历史；整表 diff 与 SQL 反解析无法可靠区分“改名”与“删列再加列”（破坏稳定对象 ID），且强依赖影子库。
- **MCP 逐操作写多条 `room_commits`，历史 UI 按批次 ID 折叠**：一次调用占用几十个 `seq`、触发几十次广播，分页游标、快照与恢复都要重写区间语义。
- **底层原地合并人类连续编辑，或仅前端按页视觉折叠**：原地改写会破坏协作客户端锚定的 `seq` 与审计；前端折叠会在分页边界劈断会话，且拿不到整组净差异。
- **提交前对模型校验或目标版本兼容性硬拦截**：包含历史遗留问题的项目无法局部修改，也会阻断分步草稿编辑。
- **开放恢复画布历史的写工具**：整库级覆盖，易误退他人刚确认的修改；有了单条原子历史，人可在画布历史中一键撤销 AI 的整批修改。
