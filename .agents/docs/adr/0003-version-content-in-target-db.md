# 目标库里存每个版本的完整内容，丢了平台数据也能接手

2026-11-19 决定：Dowel 在目标库里写迁移历史时，不只记“执行到第几版 + 校验和”（Flyway、Alembic、Django 的做法），还存每个版本的完整模型（含对象 ID、名字锁定）和冻结的升级 / 回滚脚本。历史固定放在目标库的独立 schema `dowel` 里（不提供改名；同一个库里的多个项目按项目区分，共用这个 schema）；没有建 schema 的权限时直接报错，不退回到业务 schema；不支持 schema 的数据库用同库里 `dowel_` 前缀的表。

只记版本号的话，新的 Dowel 实例接手时只能重新读库结构：对象 ID 全部重新生成，下一次改名会被当成先删后加，名字锁定和历史脚本也丢了，这正是 Dowel 区别于按名字比较的工具的地方。代价是生产库里多出 Dowel 自己的数据（只有结构，没有业务数据；PG 会压缩大字段，估计上百个版本也只有几 MB，尚未实测），每次执行多写一行。
