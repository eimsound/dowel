# 不做模型分支与语义合并引擎，改用链尾版本作废与画布复制粘贴

2026-11-24 决定（取代 Q10 / Q24 及原 M3-B 基于分支的模型评审）：Dowel 保持单主干工作副本，不做 Git 风格的模型分支与重放合并引擎；改为以**链尾版本作废与公共祖先切换**及**同方言画布/历史/跨画布复制粘贴**解决并行改表、发错版本回滚与对象复用痛点。

1. **链尾版本作废（Retire）与公共祖先切换（`v5 → v4 → v6`）**：
   - **作废范围**：允许一次作废活跃主链最末尾的 1 个或多个连续非首版本（不区分是否曾在生产环境执行，作废不依赖连目标库；由后续执行预演与审批显式标注 `down` 回滚段兜底）。
   - **软作废与号段递增**：统一软作废、版本号只增不重用（例如作废 `v5` 后，基于 `v4` 发布的新版本为 `v6`、`parent = v4`）；作废默认将工作副本回退到该段父版本（可勾选保留当前工作副本），作为新提交记入画布历史不丢数据。
   - **权限**：被作废段均从未在任何环境执行过时，项目编辑者（`editor`）可作废；只要其中任一版本已在任意环境执行过，须项目管理员（`admin`）作废；所有作废均写入审计日志。
   - **执行与 CI**：Web 端支持基于最近公共祖先的一键混合切换路线（`down → up`，如 `v5 → v4 → v6`），预演页与执行申请单显式标出回滚段并同时满足回滚与执行策略；CI 令牌默认禁止自动 `down`（返回明确错误码交人工确认）。
   - **约束与反悔路径（防丢数据双保险）**：禁止再主动执行（`up`）或标记为已执行（`mark`）到已作废版本（停在其上的环境仅可切回活跃主链或向祖先回滚）；关联未执行的执行申请自动失效，存在 `claimed` 执行中版本时拒绝作废。反悔与不可回滚救回分两层：
     - **未发新版前一键取消作废**：当且仅当尚未发布任何更新版本（即待恢复段恰好是从当前活跃链头连续衔接到全局最大编号的已作废链尾）时，允许按同级权限（整段未执行过为 `editor`，任一版本执行过为 `admin`）一键取消作废并恢复为活跃主链（此前已失效的旧执行申请不复活，弹窗可选是否将工作副本同步切回恢复后的链头，写审计）；既严格保持“根到最大编号即活跃主链”的接手不变式，也让刚误作废线上版本的场景原地无损恢复。一旦基于父版本发布更新版本，旧岔路永久锁定不可取消作废。
     - **已发新版后的零丢数据兜底**：版本页为任意版本（含已作废版本）提供一键「应用到画布」（复用画布历史差异确认与新提交机制）；同时 `mark`（标记为已执行，ADR 0004）支持从已作废版本跨岔路零 SQL 标记到结构一致的活跃主链版本（`skipped` 改为沿 `parent_id` 取最近公共祖先到目标的活跃链段，不卷入无关已作废版本），保障无法承受 `down` 丢数据的环境零停机切回活跃主链。
   - **目标库与接手（Takeover）兼容**：四方言目标库 `dowel.versions` / `dowel.history` 表结构与 `format_version = 1` 保持零改动，不新增作废列或 `direction` 枚举；放宽 `verifyChain` 与多环境接手 `mergeHistories` 为“版本号唯一递增 + 合法父链树 + 根到最大编号的唯一路径即活跃主链（其余岔路自动识别为已作废），同号不同 `version_id` 才判 `history_fork`”。
2. **同方言画布 / 画布历史 / 跨画布复制粘贴**：
   - 覆盖当前画布、画布历史、同方言跨项目；支持「单/多张表」和「表内列/约束/索引」两级粒度。
   - 粘贴一律生成全新 UUIDv7，同名自动加后缀绝不静默覆盖，指向未选中外部既有表的外键按 `(schema, 表, 列)` 自动重连（找不到则跳过并提示），经正常同步层 mutator 提交；既有老表的零星并发改动由人工补改。

未来若仍需发布前设计评审，围绕“工作副本 vs 链头 diff”独立评估，不再依赖模型分支。

## Considered Options

- **完整模型分支 + 12 类语义冲突重放合并引擎**：原生支持多人并行深度修改既有老表（保留改名意图）与独立分支评审，但正常工程实践以新增表与零星加列/加索引为主，长期随 mutator 与多方言演进维护重放合并及多分支状态机的复杂度和成本远超收益。
- **物理删除已执行链尾并重用版本号**：打破目标库 `dowel.history` 只追加触发器（ADR 0003）与 `unique (project_id, number)` 契约，且在多环境接手和沟通中造成同号歧义。
- **目标库新增 `retired_at` 列或 `direction = 'retire'`**：仅覆盖“刚作废尚未发布新版本瞬间平台库丢失”的极窄窗口，却迫使作废动作联网写所有目标库或修改四方言 DDL 与历史格式版本。
- **无条件支持任意旧岔路“取消作废”**：一旦已基于父版本发布新版本，任意旧岔路复活会制造双活跃头、连环恢复顺序混乱及工作副本错位；将取消作废严格限定在“未发更新版本前（含全局最大编号的连续作废尾段）”，既解决手滑秒撤，又杜绝双活跃头并保持目标库零加列的接手定理；发新版后的不可回滚救回交给「应用到画布」+ `mark` 跨岔路零 SQL 切换完成。
