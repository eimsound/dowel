# 一个实例只服务一家公司，用“组”统一承载人和项目归属

2026-11-19 决定：一个 Dowel 实例只服务一家公司。公司内部用**组**划分：组是一群用户，可以拥有项目，一个用户可以属于多个组。组和用户对所有人可见，组的项目只对有权限的人可见（无权限时当作不存在）。不另设“组织”和“团队”两层。

当天先定过“类似 GitHub 的多组织 + 组织内团队”，后来用一家真实公司推演时推翻了：只有一家公司时，组织其实就是部门，再在下面套团队，是两层几乎一样的概念；而跨部门的 DBA 只能被重复加进每个组织、在每个组织里各建一个 DBA 团队。合并成组以后，跨组的特权（如 DBA 执行生产迁移）通过在某个范围内授权给组来表达。也因为只服务一家公司，组级的“必须通过某个 OIDC 登录”永远不做。以后若要支持多家公司共用一个实例，需要在组之上加一层租户，并重做所有归属和权限检查。
